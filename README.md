# Vyapar Hub

An AI business copilot for small Paytm merchants (kirana stores, tea stalls), built for the
Paytm Build for India AI Hackathon, Track 1. The merchant talks to it in Hindi or Hinglish, by voice or text,
and hears back through a simulated Paytm Soundbox.

> **Demo data notice.** Every merchant, customer, phone number, VPA and rupee amount in this project is
> synthetic, generated by a seeded script. **No real money moves anywhere**, no real messages are sent, and the
> app never asks for a real UPI PIN: approvals use a mock demo PIN (`1234`).

## What it does

Five agents share one loop: **notice → suggest → merchant approves → act → confirm**.

| Agent | Notices | Suggests / does |
|---|---|---|
| Subah ki Report | Yesterday's sales vs a usual day, today's bills and udhaar | A spoken morning briefing on the Soundbox |
| Cash Radar | A 14-day balance forecast (LightGBM p10/p50/p90) dipping below the cash buffer | Moving one supplier bill to a safe date (what-if preview) |
| Supplier | Upcoming bills, messy ledger names ("M/S A.T. KNP") | Pay or reschedule, fuzzy and LLM ledger matching, GST CSV export |
| Udhaar | Credit given by voice ("Sunita ji ne 650 ka udhaar liya…") | Due-date reminders with a UPI link; auto-closes when she pays |
| Growth | Regulars who stopped coming, peak hours, slow days, festival lift | A one-tap win-back offer, sent only to opted-in customers |

### Safety rules the code enforces

- **Numbers only come from tools.** The LLM never does arithmetic on money. A server-side number guard replaces
  any reply that contains a figure not found in a tool result. "How I got this" shows the tool trace.
- **Money and messages move only on approval.** Every pay, reschedule, credit or message is a `PendingAction`,
  shown with a read-back, and runs only after `POST /actions/{id}/approve` with the demo PIN.
  Supplier and cash actions always need the PIN; udhaar and growth can be set to auto.
- **Consent.** Reminders go only to numbers the merchant typed in; win-back goes only to `opted_in` customers;
  payer IDs are stored as hashes, never raw VPAs.
- **Offline fallbacks.** No Groq key: a rule-based Hindi/Hinglish parser takes over. No Sarvam key: browser speech.
  Messages are always on-screen previews (WhatsApp sending is not enabled). The status bar shows the active mode.

## 3-minute demo script

Open the app with `?demo=1` for the presenter controls.

1. **▶ Briefing**: the morning report plays on the Soundbox.
2. **Cash** tab: shortfall on day 5. Say *"Agarwal ka payment 7 tareekh ko kar do"* → read-back → PIN `1234` → the chart redraws.
3. Say *"Sunita ji ne 650 ka udhaar liya, Friday tak denge"* → logged. **⏩ Jump to Friday** → the reminder preview with a UPI link.
   **₹ Sunita pays 650** → the Soundbox announces it and the udhaar closes.
4. **Growth** tab: "14 regulars 3 hafte se nahi aaye" → one-tap win-back → approve.
5. **How I got this** (desktop sidebar) shows each tool call behind the last answer.

**↺ Reset** (`POST /demo/reset`) restores the exact starting state.

## Architecture

```
frontend/  React 19 + Vite + Tailwind v4 + Recharts      → Vercel
backend/   FastAPI + SQLModel (SQLite) + LightGBM         → Render
           agent/    tool-calling loop (Groq, OpenAI-compatible) + rule-based fallback + number guard
           services/ forecast, udhaar, suppliers, growth, speech (Sarvam), executor (approvals), time travel
           scheduler APScheduler on a simulated demo clock (reminders at 10:00, briefing at opening time)
```

## Run locally

Requires **Python 3.10** and **Node 22** (or 20.19+).

```bash
# backend
cd backend
python -m venv .venv && .venv/Scripts/activate      # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                                # add keys (optional)
uvicorn app.main:app --reload --port 8000           # seeds the demo DB on first start
python -m pytest -q

# frontend
cd frontend
npm install
npm run dev                                         # http://localhost:5173/?demo=1
npm test
```

### Environment variables (`backend/.env`)

| Variable | Default | Purpose |
|---|---|---|
| `GROQ_API_KEY` | empty | LLM (free tier works; model `GROQ_MODEL=openai/gpt-oss-120b`). Empty = rule-based mode |
| `SARVAM_API_KEY` | empty | Speech: Saaras v3 STT, Bulbul v3 TTS. Empty = browser speech |
| `DEMO_PIN` | `1234` | The mock approval PIN |
| `DEMO_DATE` | today (IST) | Pin the demo to a date for a repeatable run |
| `CORS_ORIGINS` | localhost:5173 | Comma-separated allowed frontend origins |
| `ENABLE_SCHEDULER` | `true` | Background reminders, briefing and model warm-up |
| `ENABLE_HARDWARE` | `false` | Mirror Soundbox announcements to an Arduino display over USB serial (local rig only) |

The frontend reads `VITE_API_URL` (default `http://localhost:8000`).

Secrets live only in `backend/.env`, which is gitignored. Only `.env.example` is committed.

## Deploy

**Backend (Render).** New → Blueprint → pick this repo; `render.yaml` defines the service.
Set `GROQ_API_KEY`, `SARVAM_API_KEY` and `CORS_ORIGINS` (your Vercel URL) in the dashboard.
The free plan sleeps after 15 idle minutes: open `/health` a minute before presenting.

**Frontend (Vercel).** Import the repo with **Root Directory = `frontend`** and set
`VITE_API_URL` to the Render URL. `vercel.json` adds the SPA rewrite so deep links like `/cash` work.
